# Component inventory

Every item shipped by the reno registry, with where it came from and under what
license. **The table below is generated** from the `meta` block of each
`registry/items/*.json` by `scripts/check-provenance.mjs`, which fails CI if an
item lacks a source or carries a license other than `MIT` or `original`.

This file ships with every handover. It is the customer's record of what they
now own and what they are allowed to do with it.

## License rules

reno-ui is public open source under MIT. Only two origins may ship here:

| Source | License | Allowed |
|---|---|---|
| `shadcn/ui` | MIT | Yes — copy, adapt, redistribute. Record the upstream ref. |
| Written by us | `original` | Yes. |
| Anything else | — | No, unless reviewed and added to this table. |

### Hard constraint: `zerostaticthemes/square-ui`

`square-ui` is under the **ln-dev UI License**, a proprietary commercial license
— not MIT. It explicitly forbids:

> - "Redistribute, share, or publish the Components or Templates (or any derivatives) as standalone resources"
> - "Create or distribute a UI kit, component library, template collection, or design system based on these Components or Templates"
> - "Make the Components or Templates available in any repository, marketplace, or website (free or paid)"

Clause 2 is a precise description of what reno-ui is. Clause 3 blocks putting it
in a repository at all. reno-ui is public, so a violation would be visible to
everyone.

**What is allowed:** looking at square-ui in a browser to study layout, then
writing our own implementation from scratch.

**What is not:** cloning the repo, opening its source files, copying any code,
or "adapting" a file. `scripts/check-provenance.mjs` rejects any row citing it.

## Adding an item

1. Add the component under `registry/reno/`.
2. Create `registry/items/<name>.json` with complete `dependencies` (npm) and
   `registryDependencies` (other reno items). Missing entries are the most
   common way to break a consuming project.
3. Fill its `meta` block: `source`, `license`, `upstream`, `added`, `group`.
   `upstream` should be specific enough that someone can diff against the
   original later. The table above is generated from these blocks, and CI fails
   if any are missing — provenance cannot be forgotten.
4. Run `npm run check:all`.

Because `meta` ships with the item, an installed component carries its own
origin and license into the customer's repository.
